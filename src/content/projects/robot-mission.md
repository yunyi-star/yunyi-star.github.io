## 做的是什么

一个把移动底盘、视觉感知和机械臂组合起来的机器人任务系统。机器人需要到达任务点，按任务类型执行观察、等待、抓取或放置，再继续下一段路线。

难点在于模块之间的配合：导航成功不等于识别有效，识别到了目标也不等于机械臂已经准备好。任务层必须知道当前在等什么，以及什么时候应该取消、重试或回到安全状态。

## 工程组成

| 模块 | 实现内容 |
| --- | --- |
| 导航适配 | 封装目标发送、朝向调整、超时、重试与取消 |
| 任务调度 | 根据到达点的动作类型分发侦察、信号灯等待、抓取与投放 |
| 视觉推理 | 图像预处理、ONNX 推理、检测结果后处理 |
| 机械臂联动 | 标记位姿转换到机械臂基座坐标系，组织抓取与放置动作 |
| 异常恢复 | 等待有效关节状态、动作看门狗、取消与复位逻辑 |

## 实际遇到的问题，怎样追到根因

**投放点看起来不准，实际是释放后的动作把物块扫飞。** 原来让末端后退一点再求 IK，却出现大幅腕部回旋。排查把到位、放气、脱离和回位拆开观察，才把故障定位到脱离动作；随后在确认过的槽位姿态下，改用第一关节的小幅关节空间动作，避免这一段重新选择 IK 构型。

**驱动返回成功，机械臂却还没停稳。** 提前读取到中间关节角，既会影响脱离目标，也会让下一次规划的起点与设备状态不一致。实现增加了有效反馈等待和连续关节角采样，而不再只依赖指令返回值。

**一个动作挂住，整条任务链随之停住。** 调度器加入新鲜标记检查、总时限、取消与复位路径。不过，超时后后台复位与下一项任务的设备所有权仍需要更明确的约束；“不再阻塞主线程”不能写成“旧动作一定停止”。

## 一个关键取舍

任务调度和具体设备动作分开。调度器描述“到达后做什么”，导航器和机械臂模块处理“如何完成动作”。这样，同一段任务逻辑可以在不同的设备状态下选择重试、退出或复位，而不是把整条任务链写成一串固定延时。

对机械臂动作尤其需要区分三个时刻：指令发出、设备反馈有效、动作完成。超时分支也必须收敛到明确状态，不能让下一段导航和未结束的动作同时运行。
