# 作品集内容边界

本站发布项目概述、经核对的实现说明、工程取舍和使用虚构数据的独立示例。这里的公开说明不代表原项目仓库或其全部内容可公开。

## 内容规则

- 新内容从空白文件整理，只保留可公开的工程知识；不直接复制整个工作目录。
- 团队项目表述为项目实践，不能把上游框架、厂商驱动或未完成计划算作独立成果。
- 不能复核的指标、比赛成绩、真实设备演示与个人分工，不作为已验证成果发布。
- 示例必须标明与实际工程的区别，使用虚构输入，不携带实际连接和部署参数。
- 只有确认已公开的仓库才提供外部代码链接。
- 原有数据与依赖的授权条件保持不变；公开仓库链接不意味着可以再分发其中所有素材。

## 保留在非公开环境的材料

凭据、私有网络与设备标识、人员信息、内部操作记录、原始提交历史、实际地图与路线、个人文件、缓存、训练数据、模型权重、未获再分发许可的资料，以及不适合公开的协议与实验细节。

## 每次发布

1. 阅读将发布的差异，确认没有把本地评估记录或原始材料加入仓库。
2. 为新增的可公开文件更新 `publication-manifest.json`，保持精确文件清单。
3. 运行 `npm run check:public`、`npm test` 与 `npm run build`。
4. 检查页面与演示，并检查构建产物中的链接和内容。

自动检查会拦截未列入清单的文件、常见凭据格式、部分个人路径与私有地址。它不能替代对语义、著作权、图片或历史泄露的人工判断。

更正网页或删除当前文件不会清除既有 Git 历史、缓存与外部副本。如已有凭据泄露，应先撤销或轮换凭据，再单独处理历史；不要把网页改写视为完成清除。
